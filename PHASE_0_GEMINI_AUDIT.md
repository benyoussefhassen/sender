   - L'inspection du code de test embarqué dans `SenderProMacApp.swift` (`runRealEndToEndIntegrationSuite` L142–425) démontre que ces tests reposaient sur des **simulations locales** :
     - **Suite 04 (29 connecteurs B2B)** : `B2BConnectorEngine.runAll29ConnectorsIndividualAudit()` (`B2BConnectorEngine.swift` L485–560) n'effectue **aucune requête HTTP**. Il génère une unique chaîne HTML synthétique en mémoire (L498–519) et affecte `httpStatusCode: 200` en dur (L546).

     - **Suite 03 (SMTP)** : `RealSMTPEngine.swift` (L299–359) utilise l'hôte spécial `socketpair.tls.local` qui relie deux threads Python en mémoire via `socket.socketpair()`.
     - **Suite 02 (Sécurité)** : Vérifie que `SenderPro.sqlite` ne contient pas le mot de passe en clair, mais omet de vérifier `AppData/.vault_master_key`, où `CredentialVault.swift` (L108–109) écrit la clé maîtresse AES-256 en clair sur le disque à côté de `credentials_vault.aesgcm`.

## 9. AUDIT TELEGRAM (PHASE G)

L'inspection de `TelegramMTProtoEngine.swift` (L1–260) et de `ManageBrowsersAndContentModals.swift` (L470–612) établit la distinction suivante :

1. **Absence totale de protocole MTProto :**
   - Sous Windows (`ref/Sender Pro Marketing/`), l'application embarque `WTelegramClient.dll` (413 Ko) et `OpenTl.Schema.dll` (1,1 Mo) qui implémentent le protocole binaire MTProto 2.0 (transport TCP Obfuscated2 vers les Data Centers Telegram `149.154.167.50:443`, échange de clés Diffie-Hellman 2048 bits, chiffrement AES-256-IGE et appels RPC TL).
   - Sous macOS (`TelegramMTProtoEngine.swift`), **aucune connexion socket MTProto, aucun handshake Diffie-Hellman et aucune sérialisation TL n'existent**.
2. **Simulations identifiées dans les sessions et l'authentification :**
   - **Création de session factice en Suite 06 (`SenderProMacApp.swift` L355 & `TelegramMTProtoEngine.swift` L120–160) :** `createSQLiteSessionFile` crée une base SQLite locale avec une table `sessions` et y insère `Data(repeating: 0xAB, count: 256)` comme `auth_key`. Cette clé arbitraire n'est reconnue par aucun serveur Telegram.
   - **Login UI sans OTP (`ManageBrowsersAndContentModals.swift` L584–607) :** Cliquer sur le bouton `Login` dans `Manage Telegram` enregistre directement un `TelegramSessionRecord` avec `isConnected: true` dans SQLite et ouvre `https://web.telegram.org` dans `WKWebView`, sans jamais envoyer `auth.sendCode` ni demander de code OTP.
   - **Bouton `Load - Sessions` (L505–525) :** Ajoute n'importe quel fichier `.session` avec `isConnected: true` sans même appeler `inspectSessionFile`.
   - **Bouton `Filter Selected Accounts` (L537–539) :** Affiche en dur `"Verified all selected Telegram sessions: 100% active."` sans effectuer la moindre requête réseau.
3. **Telegram Bot API (`TelegramMTProtoEngine.swift` L230–259) :**
   - La méthode `callOfficialTelegramBotAPI(botToken:method:parameters:)` effectue une vraie requête `POST https://api.telegram.org/bot<token>/<method>`, mais **elle est orpheline (0 appel dans tout le projet et aucun champ UI pour saisir un Bot Token)**.
4. **Scraping public `https://t.me/s/<channel>` (`TelegramMTProtoEngine.swift` L164–227 & `ExecutionEngine.swift` L291–294, L328–348) :**
   - **`VERIFIED_REAL`**. Lorsqu'un utilisateur saisit un lien `https://t.me/<channel>`, `ExecutionEngine` le convertit en `https://t.me/s/<channel>`, télécharge la page web publique et extrait réellement le compteur d'abonnés (`tgme_header_counter`), les messages (`tgme_widget_message`), les auteurs et toutes les mentions `@username`.
5. **Évaluation de l'intégration MTProto sur macOS :**
   - Pour obtenir une parité réelle avec `WTelegramClient.dll` sur les comptes utilisateurs Telegram (login téléphone + OTP + 2FA, extraction/ajout de membres, broadcast DM/groupes), deux options techniques viables existent sur macOS :
     - **Option A (Recommandée — Native C/Swift) :** Intégrer **`TDLib` (`libtdjson.dylib` via `TDLibKit`)**, la bibliothèque officielle multiplateforme de Telegram, qui gère nativement tout le protocole MTProto 2.0, le chiffrement local de la base de session et les appels `sendCode`/`checkAuthenticationCode`/`getSupergroupMembers`/`addChatMember`/`sendMessage`.
     - **Option B (Pont Python local) :** Utiliser un sous-processus Python (`Telethon` ou `Pyrogram`) piloté via `stdin`/`stdout` JSON, compatible nativement avec le format SQLite `.session` déjà préparé dans `TelegramMTProtoEngine.swift`.

## 10. AUDIT SMTP / POP3 (PHASE H)

L'inspection de `RealSMTPEngine.swift` (L1–571), `ExecutionEngine.swift` (L564–709) et `ToolExecutionPanelView.swift` (L698–979, L1404–1435) met en évidence :

1. **Ce qui fonctionne réellement (`VERIFIED_REAL`) :**
   - Construction MIME RFC 2046 (`buildRFC2046MIMEMessage` L29–136) : `multipart/mixed` + `multipart/alternative` (`text/plain` Base64 + `text/html` Base64), encodage UTF-8 RFC 2047 `=?UTF-8?B?...?=` des en-têtes `Subject` et `From`, *dot-stuffing* RFC 5321 (`\r\n.` -> `\r\n..` à L435) et encodage Base64 des pièces jointes binaires.
   - Handshake TLS implicite (port 465) et `STARTTLS` explicite (port 587) avec validation stricte des certificats X.509 (`ssl.CERT_REQUIRED`, rejet avec code `495` si le certificat serveur est auto-signé/invalide) et authentification `AUTH PLAIN` / `AUTH LOGIN` via `/usr/bin/python3`.
2. **Les 6 défauts critiques et majeurs identifiés dans le moteur et l'assistant SMTP :**
   - **Secret SMTP écrit en clair dans un fichier temporaire (`RealSMTPEngine.swift` L214–243 — `CRITICAL`) :** `sendEmailOverRealTCP` déchiffre le mot de passe SMTP et l'écrit en clair dans `/var/folders/.../T/smtp_cfg_<UUID>.json` (permissions par défaut `0644`) avant d'appeler `/usr/bin/python3`.
   - **Repli silencieux en clair si `STARTTLS` n'est pas annoncé (`RealSMTPEngine.swift` L383–398 — `HIGH`) :** Sur le port 587 avec `use_ssl = True`, si le serveur (ou un attaquant MITM) n'inclut pas `250-STARTTLS` dans sa réponse `EHLO`, le `if "STARTTLS" in ehlo_resp.upper():` (L384) est ignoré et le client envoie `AUTH PLAIN` / `AUTH LOGIN` **sur la connexion TCP non chiffrée** !
   - **Bouton `Stop` invisible et inopérant pendant l'envoi (`ToolExecutionPanelView.swift` L879–886, L946–977 — `HIGH`) :** `runRealSMTPCampaign()` lance `Task { ... }` sans mettre `engine.isRunning = true` ni assigner `engine.currentTask`. Le bloc `if engine.isRunning` (L879) qui affiche le bouton `Stop` n'est donc jamais évalué à `true`, rendant toute campagne lancée impossible à arrêter.
   - **Duplication massive des destinataires `CC` (`ToolExecutionPanelView.swift` L935–969 — `HIGH`) :** La boucle `for (idx, recipient) in smtpRecipients.enumerated()` envoie un email individuel à chaque destinataire `To`, mais passe `ccRecipients: ccList` (L963) à **chaque itération**. Si la liste `To` compte 500 clients, chaque adresse en `CC` reçoit 500 copies du même email.
   - **Paramètres de serveur absents de l'interface (`ToolExecutionPanelView.swift` L41–43, L746–791 — `MEDIUM`) :** Les variables `@UIState` `smtpHost`, `smtpPort` et `smtpUseSSL` sont déclarées aux lignes L41–43 mais aucun `TextField` ni `Toggle` ne permet de les saisir à l'étape 1, et il n'existe aucun champ `BCC` à l'étape 3. De plus, `acc.sendLimitCount` (L728) n'est jamais respecté dans `runRealSMTPCampaign()`.
   - **Code mort en doublon (`ExecutionEngine.swift` L564–709 — `LOW`) :** Une ancienne implémentation `sendRealSMTPEmail` basée sur `NWConnection` subsiste dans `ExecutionEngine.swift` sans jamais être appelée.

## 16. LISTE DES RISQUES TECHNIQUES, SÉCURITAIRES ET OPÉRATIONNELS

1. **Risque de compromission des identifiants locaux (`CRITICAL`) :** Tant que `AppData/.vault_master_key` et les fichiers temporaires `/var/folders/.../T/smtp_cfg_*.json` existent, tous les mots de passe enregistrés dans l'application sont exposés localement.
2. **Risque de blocage anti-bot (Cloudflare / DataDome / reCAPTCHA) sur les portails B2B (`HIGH`) :** Les portails comme `Haraj`, `OpenSooq`, `Dubizzle`, `Bayut`, `Property Finder` et `Oued Kniss` bloquent les requêtes HTTP automatisées issues de `URLSession`. L'extraction doit impérativement passer par le `WKWebView` interactif de l'utilisateur (où les défis Cloudflare Turnstile peuvent être résolus dans la session navigateur).
3. **Risque de suspension de comptes sociaux (Anti-Ban) (`HIGH`) :** Les plateformes sociales détectent les rafales d'actions automatisées. Le moteur d'action DOM doit systématiquement respecter les délais aléatoires (`securityConfig.minTimerSeconds...maxTimerSeconds`) et les pauses périodiques (`stopEveryCount` / `waitMinutesOnStop`) configurés par l'utilisateur.
4. **Risque de fuite accidentelle de données sensibles lors d'une initialisation Git future (`MEDIUM`) :** En l'absence de fichier `.gitignore`, le dossier `version-mac/AppData/` (qui contient actuellement `SenderPro.sqlite`, `.vault_master_key`, `credentials_vault.aesgcm` et les cookies `SenderProBrowsers/*.json` copiés depuis `ref/`) serait indexé par un `git add .`.
